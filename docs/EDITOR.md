# Интерактивный 3D-редактор (этап 5)

Надпись (потом — логотип) ставится мышью или пальцем прямо на поверхность модели в окне
3D-просмотра, прилипает к ней, двигается по ней, крутится вокруг нормали, масштабируется.
Форм «введите координаты» нет. Раскраска — кликом по детали (B63). Каркас — B60 (2026-11-01).

## Где что лежит

| Файл | Что там |
|---|---|
| `web/app/upload/[id]/edit/page.tsx` | Страница редактора: окно на весь экран, панель инструментов (слева на десктопе, снизу на телефоне), панель параметров (справа / над инструментами). Инструменты: «Текст», «Логотип» (заглушка до B62), «Цвет» (PaintPanel как есть), «Готово» (назад на `/upload/[id]`). Esc — снять выбор, Delete — убрать выбранную надпись. |
| `web/lib/editor/store.ts` | Состояние редактора: инструмент, список наложений с размещением, выбранное, предпросмотр под курсором, режим гизмо, черновик. Чистый `reduce(state, action)` + хранилище `createEditorStore()` на `useSyncExternalStore` (без сторонних библиотек). `toEmbossParams(overlay)` — тело запроса к API. |
| `web/lib/editor/math.ts` | Математика без three.js: касательная система `tangentFrame`, поворот «верха» вокруг нормали, перевод сцена ↔ модель, матрица размещения для three.js. Тесты — `math.test.ts`, `store.test.ts`. |
| `web/components/editor/EditorCanvas.tsx` | 3D-окно: модель, raycast под курсором → плашка-предпросмотр, клик → наложение, гизмо `TransformControls` у выбранного. |
| `web/components/editor/TextToolPanel.tsx` | Панель «Текст»: текст, шрифт, размер, глубина, выпукло/врезано, переключатель гизмо, поворот кнопками ±15°, «Применить» → сервер → страница результата. |

Вход в редактор — кнопка «Открыть редактор» в блоке «Дополнительно» на странице модели.

## Две системы координат

- **Модель** — как в файле клиента и в OpenSCAD на сервере: мм, Z вверх. В ней хранится
  размещение и в ней его принимает API. Если файл в дюймах, координаты уже умножены на 25,4
  (сервер делает то же в `load_model`).
- **Сцена** three.js — Y вверх. Окно поворачивает модель на −90° вокруг X и сдвигает так,
  чтобы она стояла на полу по центру (`SceneFit.offset`). Переводы: `sceneToModel`
  `(x, y, z) → (x, −z, y)` минус сдвиг; `modelToScene` — обратно. Нормали — то же без сдвига.

## Размещение (контракт API)

`POST /api/v1/uploads/{id}/embosses`, тело `{"params": {...}}`, в `params`:

```json
"placement": {
  "point":  [x, y, z],   // точка на поверхности, мм, система модели
  "normal": [x, y, z],   // нормаль наружу (сервер нормирует)
  "up":     [x, y, z],   // куда смотрит верх букв (сервер проецирует на касательную плоскость)
  "size_mm": 10, "depth_mm": 1, "mode": "raised" | "engraved"   // перекрывают size_mm/depth_mm/style
}
```

Остальные поля `params` (`kind`, `text`, `font`, `bold`) — как раньше; `face`, `dx`, `dy`,
`angle` при наличии `placement` не используются. Ошибки — 422 `{"detail": {"errors":
{"placement.normal": "..."}}}`. Одинаковое размещение (с точностью до нормировки) → тот же
`job_id` → та же сборка.

Локальная система тиснения (`tangent_frame`, одинаково на сервере и клиенте):
`normal` — ось Z фигуры из OpenSCAD («лицом» наружу); `up` — проекция подсказки на касательную
плоскость → ось Y; если подсказка параллельна нормали — «верх» модели +Z, на горизонтальной
грани — +Y (как у старого `face="top"`); `right = up × normal` — текст читается снаружи.
Матрица 4×4: столбцы right, up, normal, точка. Фигура из OpenSCAD лежит в плоскости XY с
центром в нуле и запасом `overlap` 0,3 мм внутрь модели — этого хватает для плоских и слегка
выпуклых поверхностей.

### Проверка касания (B64, `check_placement` → `check_contact`)

Сразу в `POST /embosses`, до постановки в очередь: модель загружается, считается расстояние
от точки размещения до поверхности (`surface_distance` — ближайшая точка на каждом
треугольнике через numpy, без rtree; 330 тыс. треугольников ≈ 0,2 с). Дальше
`CONTACT_TOL_MM` (1 мм) → 422 `{"errors": {"placement.point": "Надпись не касается
поверхности модели (до неё N мм) — поставьте её на модель заново."}}`, сборка не создаётся.
Если нормаль смотрит внутрь (вывернутая сетка клиента) — разворачиваем наружу, `up`
сохраняем, в `warnings` — `normal_flipped` (и в кэшированном ответе тоже). На сильно
выпуклых поверхностях (сфера меньше надписи) края букв могут «повиснуть» над поверхностью —
запас 0,3 мм не спасёт; это ограничение, лечится в B61+ изгибом текста по поверхности или
большим overlap для кривых граней (см. бэклог).

Производительность: предпросмотр целиком на клиенте (плашка/текст в three.js), сервер в
нём не участвует. Сборка на сервере: OpenSCAD (секунды) + manifold (union/difference на
500 тыс. треугольников — единицы секунд); её время ограничивает таймаут worker (`app/jobs.py`).

## Как ведёт себя гизмо

- **Двигать** (`translate`, локальные оси X/Y = касательная плоскость, Z скрыта): после каждого
  сдвига луч вдоль нормали (туда и обратно) ищет поверхность, плашка встаёт в точку попадания с
  новой нормалью; старый `up` проецируется на новую плоскость. Ушёл за край грани — плашка
  остаётся на последней точке поверхности. Переход «за угол» — следующая задача (см. бэклог).
- **Повернуть** (`rotate`, только локальная Z = нормаль): новый `up` = локальная ось Y группы.
  Те же ±15° — кнопками в панели (`rotateUp`).
- **Размер** (`scale`): коэффициент масштаба группы × `size_mm`, масштаб группы сбрасывается.
- Клик по модели, пока наложение выбрано, снимает выбор (во время перетаскивания гизмо клик
  игнорируется — флаг `dragging`). Поворот камеры (`e.delta > 5`) кликом не считается.
