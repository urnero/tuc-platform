# Telegram-бот BroPrint

Один бот на двоих: **владелец** получает заказы и меняет статусы, **клиент** получает статусы своего заказа.
Код: `api/app/bot.py` (команды и кнопки, aiogram 3), `api/app/telegram.py` (тексты, кнопки, отправка из API),
`api/app/notify.py` (сообщения клиенту). Запуск — сервис `bot` в docker compose (`python -m app.bot`).

## Подключение (делает владелец, один раз)

1. В Telegram открыть @BotFather → `/newbot` → имя «BroPrint» и логин вида `broprint3d_bot`. BotFather пришлёт токен `123456:ABC…`.
2. Узнать свой chat_id: написать @userinfobot → число `Id`.
3. На сервере в `/srv/tuc/prod/.env` (и в `/srv/tuc/staging/.env`, если нужен второй, тестовый бот — **отдельный токен**: один токен нельзя слушать с двух стендов сразу):
   ```
   TELEGRAM_BOT_TOKEN=123456:ABC…
   TELEGRAM_OWNER_CHAT_ID=987654321
   ```
4. `cd /srv/tuc/prod && docker compose up -d api bot` (с `-f compose.server.yml`, как в `deploy/deploy.sh`).
5. Написать боту `/start` — должна прийти подсказка. В логах `docker compose logs bot` строка «бот @… запущен».

Без токена или chat_id бот не запускается (пишет об этом в лог), а сайт работает как обычно — уведомления просто не уходят.

## Команды владельца

Меню команд (кнопка «/» в чате) бот прописывает сам при запуске.

| Команда | Что делает |
|---|---|
| `/start`, `/help` | Подсказка по командам |
| `/orders` | Активные заказы (принят, оплачен, печатается, готов), новые сверху, до 20; под списком кнопки-номера → карточка |
| `/orders all` | Последние 20 заказов любых статусов |
| `/today` | Заказы, созданные сегодня по Москве: сколько, на какую сумму (без отменённых), сколько всего в работе |
| `/order 12` или `/order BP-12` | Карточка заказа с кнопками статусов |

## Карточка заказа

Номер, сумма, статус, клиент (имя, телефон, e-mail), материал × количество, поддержки, постобработка, доставка,
юрлицо (если заказ по счёту), время печати и граммы на тираж, имя файла, оформление (раскраска/тиснение),
комментарий, подключил ли клиент статусы в Telegram, время создания (МСК).
Последняя строка — ссылки:

- **Страница заказа** — то, что видит клиент;
- **Админка** — карточка в `/admin/orders/<id>` (только если на сервере задан `ADMIN_PASSWORD`);
- **Файлы в Drive** — папка заказа в Google Drive (появится после задачи B46).

## Кнопки статусов

Под карточкой — следующие логичные шаги (любой переход возможен и через админку):

| Сейчас | Кнопки |
|---|---|
| 🆕 принят | 💰 Оплачен (наличные при самовывозе), 🖨 Печатается, ❌ Отменён |
| 💰 оплачен | 🖨 Печатается, ❌ Отменён |
| 🖨 печатается | ✅ Готов, ❌ Отменён |
| ✅ готов | 📦 Выдан, ❌ Отменён |
| ❌ отменён | 🆕 Принят (вернуть) |

Нажатие пишет статус в базу, обновляет карточку на месте и отправляет клиенту письмо/сообщение (B34),
обновляет строку в Google-таблице (B47). Повторное нажатие того же статуса — «уже в статусе …», ничего не меняется.
Кнопка «📋 Активные заказы» — то же, что `/orders`.

## Сообщения, которые приходят сами

- **🆕 Новый заказ BP-N** — сразу после оформления на сайте (шлёт API, не бот).
- **💰 Оплачен заказ BP-N** — когда ЮKassa подтвердила оплату. Если заказ к этому моменту уже не «принят»
  (например, отменён) — внизу предупреждение «⚠️ Заказ сейчас в статусе …».

## Клиенты

На странице заказа кнопка «Получать статусы в Telegram» открывает `t.me/<бот>?start=<token заказа>`.
Бот привязывает чат к заказу и дальше присылает смену статуса. `/stop` — отписаться.
Любые другие команды и кнопки от не-владельца — вежливый отказ, статусы чужие люди менять не могут.

## Сбои сети

- Отправка из API (`telegram.send_message`): при обрыве сети или ответе 5xx — ещё две попытки через 1 и 3 с;
  при 429 (Telegram просит подождать) — ждём сколько сказано, но не дольше 10 с. Ошибки 400/401/403
  (неверный токен, бот заблокирован) не повторяем. Неудача только пишется в лог, заказ всё равно создаётся.
- Бот (long polling) переподключается к Telegram сам — это делает aiogram.
- Меню команд не прописалось (нет сети при старте) — бот работает, меню появится при следующем перезапуске.

## Как проверено без токена

Тесты `api/tests/test_telegram.py` гоняют бота целиком без сети: настоящий диспетчер aiogram получает
обновления Telegram (сообщения и нажатия), вместо сети — записывающая подмена. Проверяются все команды,
кнопки, отказ чужим, меню команд, повторы при сбоях.
