# Платформа ТУЦ — спецификация и бэклог (seed для сборки)

Версия 0.1 · 15.10.2026 · владелец: Girg (GitHub: urnero) · репозиторий: github.com/urnero/tuc-platform

## 1. Цель

Сайт студии 3D-печати ТУЦ (Москва), который принимает заказы без участия менеджера.
Клиент загружает, выбирает или собирает модель → получает цену → оплачивает → заказ попадает в учёт и в Telegram.

Целевая метрика: 40+ оплаченных заказов в месяц через сайт к концу 2027 года.

## 2. Что хочет владелец (полный объём)

1. Каталог готовых моделей по категориям (свои модели + модели с коммерческой лицензией).
2. Редакторы стандартных деталей по категориям — параметрические (размеры, отверстия, текст) → STL.
3. Редактор загруженных моделей: тиснение текста и логотипа, раскраска по частям, текстуры (упрощённая версия).
4. Серверный расчёт печати (слайсер) и рендер превью модели.
5. Выбор материала, технологии, тиража → расчёт стоимости → заказ → оплата (ЮKassa).
6. Интеграция с учётом (Google-таблица «Учет 3D-печати ТУЦ» + БД для Superset) и Telegram-бот (уведомления о заказах и оплатах, статусы).

## 3. Стек (не менять без записи в docs/DECISIONS.md)

- Backend: Python 3.12, FastAPI, SQLAlchemy 2 + Alembic, PostgreSQL 16, Redis + arq (фоновые задачи: слайсинг, рендер, экспорт).
- Слайсер: PrusaSlicer CLI (AppImage в Docker). Выдаёт время печати и граммы. Профили принтеров и материалов — в `profiles/`.
- Параметрические редакторы: OpenSCAD CLI (параметры → STL). Превью — Three.js в браузере.
- Frontend: Next.js 15 (App Router, TypeScript), Tailwind, Three.js (@react-three/fiber) для просмотра STL/3MF.
- Платежи: ЮKassa (SDK `yookassa`), вебхуки. Чеки 54-ФЗ через ЮKassa.
- Telegram: aiogram 3.
- Учёт: PostgreSQL — источник истины. Ночной экспорт заказов в Google Sheet (gspread, сервисный аккаунт). Superset подключается к Postgres напрямую (read-only пользователь).
- Инфраструктура: docker-compose (caddy, web, api, worker, postgres, redis). VPS в РФ (Ubuntu 24.04, 2 vCPU / 4 GB). GitHub Actions: тесты на push; деплой staging с ветки `dev`, prod с `main` (по SSH).
- Ветки: `dev` — рабочая (ночные сборки пушат сюда), `main` — прод. PR dev→main раз в неделю, владелец сливает.

## 4. Формула цены (v1, параметры в `config/pricing.yaml`)

```
price = max(min_order,
            (material_g × price_per_g[material] + print_h × machine_rate[tech])
            × k_supports × k_batch(qty) × (1 + margin))
        + postprocess + delivery
```

Первые значения — заглушки. Владелец заменит их на реальные из таблицы учёта.

## 5. Модель данных (ядро)

users, models (uploaded / catalog / generated), model_files, quotes (расчёты), orders, order_items, payments (yookassa), print_jobs, materials, technologies, printers, events (воронка: upload → quote → order → paid).

## 8. Правила ночной сборки

- Один запуск — одна задача из бэклога (или одна небольшая связка).
- Тесты обязательны: pytest для api, vitest для web. Пушить только с зелёными тестами.
- Секреты — только в .env (в .gitignore). В репо — .env.example с пустыми значениями.
- Код и комментарии простые. Владелец — продуктовый аналитик: знает SQL, Python на базовом уровне.
- Решения, меняющие стек или формулу цены, — запись в docs/DECISIONS.md.
- docs/STATUS.md: последняя запись сверху: дата · задача · результат · «нужно от владельца».
